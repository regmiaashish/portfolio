# CLAUDE.md

Frontend for Aashish Regmi's portfolio. The FastAPI backend is a separate repo
(`../portfolio-website-backend`), and the roadmap lives there in
`docs/PORTFOLIO_IMPLEMENTATION_PLAN.md`. Work happens one phase at a time, on its own branch.

## Safety rules (non-negotiable)

- **Never read, print, copy or commit `.env*` files**, except the committed `.env.development`
  (which only points at `http://localhost:8001`).
- **Never call the production API** from tests or scripts. Tests mock `fetch`.
- **No commits or pushes without explicit approval.** Leave changes for review.

## Commands

```bash
npm ci                 # install exactly what package-lock.json pins
npm run dev            # Vite dev server (backend expected on :8001)
npm run build          # tsc -b && vite build (fails without VITE_API_URL)
npm run preview        # serve dist/
npm run typecheck      # tsc -b
npm run lint           # eslint, zero warnings allowed
npm run test           # vitest run
npm run test:watch     # vitest
npm run check          # typecheck + lint + test
npm run e2e            # build dist-e2e/{site,pitch} and run the Playwright smoke tests (system Chrome)
npm run gen:api        # regenerate src/lib/api-types.ts (backend running with ENV=dev, or OPENAPI_URL=...)
npm run gen:brand      # regenerate public/og-image.png + icons from src/data/profile.ts (Chrome)
```

## Architecture conventions

- **All HTTP goes through `src/lib/api.ts`**: `request()` and `ApiError`. Never call `fetch`
  directly from components or hooks. `ApiError.message` is always safe to show to visitors.
  The one exception is `src/hooks/usePitchStream.ts`, which streams Server-Sent Events with
  `fetch` + `src/lib/sse.ts` (never `EventSource`, which reconnects on its own and would re-run
  the paid pipeline); it still takes `API_URL` and its errors from `api.ts`.
- **API types come from `src/lib/api-types.ts`**, generated by `npm run gen:api`. Never edit it by
  hand; regenerate after backend schema changes.
- **Public content comes from `useContent()`** (`src/hooks/useContent.ts`, provided by
  `app/ContentProvider.tsx`): starts from this visitor's cached copy of the last API response
  (localStorage, validated) or the bundled snapshot in `src/data/*.ts`, then fetches
  `GET /api/v1/content` after the first paint (`lib/afterPaint.ts`). Components never import `src/data` directly. Keep the snapshot valid:
  `src/data/snapshot.test.ts` runs it through the admin validators.
- **The admin lives in `src/admin/`** and is lazy-loaded at `/admin/*`. Admin HTTP goes through
  `src/admin/api.ts` (`adminRequest`/`adminApi`: cookies, the `X-Requested-With` CSRF header,
  one silent refresh on 401). Client validation in `src/admin/validation.ts` mirrors the backend
  contract (`portfolio-website-backend/docs/ADMIN_CMS_CONTRACT.md`). Images and the résumé upload
  through the API (`uploadViaApi`: multipart XHR to `/api/v1/admin/uploads/file`, for progress;
  the API stores the file in S3, so the bucket needs no CORS). CMS types live in `src/lib/cmsContracts.ts`,
  derived from the generated schema.
- **Head tags**: pages call `usePageMeta({ title, description, robots })`
  (`src/hooks/usePageMeta.ts`); site-wide values come from pure helpers in `src/lib/siteMeta.ts`,
  which `vite/seo.ts` also uses to inject the static tags and JSON-LD into `index.html`. Never
  hand-edit those tags in `index.html`.
- **Security headers** are generated into `dist/_headers` by `vite/headers.ts` at build time
  (CSP from `VITE_API_URL` plus SHA-256 hashes of the built `index.html`'s inline scripts).
  Never hand-write `public/_headers`. New external origins (fonts, scripts, frames, APIs) must be
  added to `contentSecurityPolicy()`, or the e2e tests fail on the CSP violation. Only the API's
  media route may be framed (`isEmbeddableResume`). Don't add long-lived caching for `/assets/*`
  (the SPA fallback serves `index.html` for missing chunks). Cloudflare Rocket Loader must stay
  off (it breaks the hash-based CSP); turning on Web Analytics needs its two origins added.
- **Admin forms** register their dirty state with `useUnsavedChanges(dirty)`
  (`src/admin/unsaved.ts`): in-app links (`GuardedLink`), logout, reload/close and the browser
  Back button all ask before discarding changes.
- **Styling is CSS Modules plus tokens only.** No hard-coded colours: add a token to
  `src/styles/tokens.css` (light, system-dark and explicit-dark blocks) and, if it is used for
  text or UI, a pair in `src/styles/contrast.test.ts`.
- **Primitives**: UI primitives in `components/ui`, layout primitives in `components/layout`;
  `components/sections` compose them; `pages/` compose sections.
- Keep components and hooks in separate files (React Fast Refresh lint rule).
- React Compiler lint rules (eslint-plugin-react-hooks 7): never pass a ref that lives inside a
  returned object straight to `ref=` (`ref={form.alertRef}`): destructure it first, or the
  compiler treats the whole object as a ref. Don't reset state synchronously at the top of a
  fetch effect: key the result to the request with `useRequestState` (`src/admin/`).

## Accessibility rules

- Every interactive element is keyboard reachable and uses the shared `:focus-visible` style.
- Touch targets are at least 44px.
- Icon-only controls need an `aria-label`; icons themselves are `aria-hidden`.
- External links use `target="_blank" rel="noopener noreferrer"` and include a visually hidden
  "(opens in a new tab)".
- Respect `prefers-reduced-motion`.
- Colour is never the only cue: `StatusDot` always carries a text label.

## Testing

- Vitest + jsdom + Testing Library. CSS is disabled in tests (`css: false`) because jsdom cannot
  evaluate media queries; test behaviour, not layout.
- Render the real app with `renderApp(url)` from `src/test/render.tsx`.
- The app uses `BrowserRouter` + `useRoutes`, tests use `MemoryRouter`; both share `AppRoutes`.
  Don't switch to a data router (`createBrowserRouter`) without fixing the jsdom `AbortSignal`
  issue it causes in tests.
- Mock `fetch` with `vi.stubGlobal`; never hit a real backend.
- Playwright smoke tests live in `e2e/` (excluded from Vitest). `e2e/fixtures.ts` answers every
  API request from fixtures and aborts every other request; each test fails on unmocked API
  calls, console errors and CSP violations. Add a fixture when the site calls a new endpoint.
